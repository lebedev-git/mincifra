# Пайплайн подачи ПО в Единый реестр российского ПО (Минцифры)

End-to-end процесс подготовки и подачи программного продукта в реестр отечественного ПO.
Построен поверх аналитической записки проекта (`../Аналитическая_записка_Реестр_ПО_Минцифры.docx`).

> **Оговорка о достоверности.** Нормативный костяк стабилен (ст. 12.1 ФЗ-149, ПП РФ № 1236,
> ПП РФ № 325, приказы Минцифры). Но **процедурные сроки и доптребования по совместимости
> менялись в 2023–2025 гг.** Значения, помеченные `СВЕРИТЬ`, обязательно проверьте на
> `reestr.digital.gov.ru` и в действующей редакции ПП № 1236 непосредственно перед подачей.

---

## Из чего состоит пайплайн

| Слой | Каталог | Назначение |
| --- | --- | --- |
| **Данные** | `product.example.json` | Единый источник истины — карточка продукта. Питает и проверки, и генерацию документов. |
| **Критерии** | `99_reference/pp1236.json` | Дословная выписка требований ПП № 1236 с правилом проверки на каждый пункт. Единственный источник критериев. |
| **Трекер** | `01_tracker/` | Операционный процесс: стадии маршрута, артефакты, ответственные. |
| **Проверки** | `02_checks/` | Технические авто-проверки (SBOM/лицензии, сетевой аудит, правило 30%, страница продукта) — доказательная база под критерии. |
| **Документы** | `03_docs/` | Генерация пакета досье под конкретный продукт из `product.json`. |
| **Справочник** | `99_reference/` | Нормативный костяк, классификатор и перечень значений под сверку. |

## Как сверяется соответствие

Требования не зашиты в код. Они лежат выпиской в `99_reference/pp1236.json`: у каждого
пункта есть ссылка на норму, дословный текст акта и декларативное правило проверки.
Движок `platform/core/criteria.js` вычисляет эти правила по карточке, отчёту проверок и
списку артефактов и отдаёт по каждому пункту один из четырёх статусов:

| Статус | Что значит |
| --- | --- |
| `ok` | требование выполнено |
| `no` | не выполнено: данных нет или значение не то |
| `n/a` | пункт неприменим к этому продукту |
| `pending` | норма для этого класса ПО ещё не вступила в силу |

Отсюда же берутся три стадии маршрута — требования (п. 5), сведения реестровой записи
(п. 4) и приложения к заявлению (п. 11). Добавить критерий — значит дописать запись в
выписку; код при этом не трогается, и правило сразу применяется к любому продукту.

```bash
node platform/core/criteria.selftest.js
```

Маршрут подготовки (`platform/core/tracker.js`, порядок массива `STAGES`):

```
Депонирование (Роспатент)         → ст. 1262 ГК, свидетельство на автора-физлицо
Отчуждение права (физлицо → ООО)  → ст. 1234 ГК, договор + акт
Регистрация перехода в ФИПС       → ст. 1232 п. 2, ст. 1262 п. 5 ГК
Предпосылки подачи                → УКЭП, ЕСИА, отсутствие долга на ЕНС
Требования к ПО                   → ПП № 1236 п. 5, подп. «а»–«н»      ← из выписки
Сведения реестровой записи        → ПП № 1236 п. 4                      ← из выписки
Приложения к заявлению            → ПП № 1236 п. 11, подп. «а»–«к»      ← из выписки
Артефакты и проверки              → SBOM, HAR, отчёт технической готовности
Подача                            → reestr.digital.gov.ru, УКЭП, «Отправить»
```

## Порядок работы

1. **Скопировать** `product.example.json` → `product.json` и заполнить под свой продукт.
2. **Вести** `01_tracker/pipeline_tracker.md` — отмечать гейты по мере готовности.
3. **Собрать артефакты** для проверок:
   - SBOM продукта в формате CycloneDX JSON (напр. `syft`/`cdxgen`) → положить рядом, указать путь в `product.json`.
   - Экспорт сетевого трафика рабочего экземпляра: DevTools → Network → «Save all as HAR».
4. **Прогнать проверки:**
   ```bash
   node 02_checks/run_checks.js product.json
   ```
   Отчёт — консоль + `02_checks/last_report.md`. Пока есть `FAIL` — на портал не идём.
5. **Сгенерировать досье:**
   ```bash
   node 03_docs/gen_dossier.js product.json
   ```
   На выходе — пакет `.docx` в `03_docs/out/`.
6. **Подать** на `reestr.digital.gov.ru` по чек-листу G4.

## Требования окружения

- Node.js (проверено на v26).
- Пакет `docx` (используется генератором досье). Ищется автоматически: локально
  или в глобальном npm-каталоге. При отсутствии — `npm install -g docx`.

## Дисклеймер

Пайплайн — инструмент подготовки и самопроверки, а не юридическая гарантия включения в реестр.
Правовые формулировки в сгенерированных документах требуют проверки юристом правообладателя.
