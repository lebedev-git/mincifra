# AGENTS.md — инструкция для агента

Ты помогаешь подготовить продукт к подаче в **Единый реестр российского ПО (Минцифры)**.
Платформа уже считает готовность сама. Твоя работа — **заполнять поля карточки данными**,
которые дал человек, и двигать продукт по стадиям. **Изучать код проекта не нужно** — всё, что
требуется, здесь.

## Как подключаешься

Через MCP-сервер `reestr-platform` (обёртка над платформой). Инструменты:

| Инструмент | Что делает |
|---|---|
| `list_products` | список продуктов + `percent`, `id`. Начни отсюда. |
| `create_product {name}` | создать новый продукт, вернёт `id`. |
| `get_product {id}` | полная карточка (объект `product`). |
| `get_checklist {id}` | 5 стадий: какие пункты закрыты/открыты, `nextStageId`. |
| `patch_product {id, changes}` | заполнить поля. `changes` — частичный `product`. Возвращает свежий чек-лист. |
| `run_checks {id}` | прогнать тех. проверки (30%, лицензии, сеть, страница). |

## Рабочий цикл

1. `list_products` → найди `id` (или `create_product`).
2. `get_checklist {id}` → посмотри, что открыто и какой `nextStageId`.
3. Человек даёт данные → разложи их по путям (таблица ниже) → `patch_product {id, changes}`.
4. Ответ `patch_product` уже содержит новый чек-лист — проверь, что нужные пункты закрылись.
5. Повторяй, пока `nextStageId` не станет `null` (все стадии закрыты).

**Правила patch:** `changes` сливается с карточкой (остальное не трётся). **Массивы заменяются
целиком** — передавай список полностью. Числа — числом, галочки — `true`/`false`.

```json
patch_product {
  "id": "маяк-око-245n",
  "changes": {
    "rightholder": { "inn": "7701234567", "ruControlSharePercent": 100 },
    "finance": { "annualRevenueProduct": 5000000, "annualForeignPayments": 0 },
    "product": { "class": ["05.09"] }
  }
}
```

## Стадии и карта полей

Чек-лист — **проекция данных**: пункт закрывается сам, когда поле заполнено. Кликать нечего.

### 1. Карточка — правообладатель, права, финансы
| Путь | Смысл | Тип |
|---|---|---|
| `rightholder.orgName` | наименование правообладателя | строка |
| `rightholder.inn` | ИНН | строка |
| `rightholder.ogrn` | ОГРН | строка |
| `rightholder.address` | адрес | строка |
| `rightholder.ruControlSharePercent` | доля РФ-контроля, **> 50** | число |
| `rightholder.signatory.hasUKEP` | УКЭП на руководителя получена | bool ⚠️ |
| `rightholder.esiaConfirmed` | учётка организации подтверждена в ЕСИА | bool ⚠️ |
| `rightholder.noEnsDebt` | нет долга на ЕНС > 3000 ₽ | bool ⚠️ |
| `rights.basis` | основание прав | `"rospatent"` \| `"internal_docs"` |
| `rights.rospatentCertificateNumber` | № свидетельства Роспатента | строка |
| `rights.chainOfTitleComplete` | цепочка прав оформлена | bool |
| `rights.authors` | авторы (ФИО) | массив строк |
| `compliance.pp325Checked` | доптребования ПП №325 сверены (если применимо к классу) | bool ⚠️ |
| `finance.annualRevenueProduct` | выручка по продукту за год | число |
| `finance.annualForeignPayments` | выплаты иностранцам за год | число |

### 2. Продукт — описание и публикация
| Путь | Смысл | Тип |
|---|---|---|
| `product.name` | наименование | строка |
| `product.shortName` | короткое имя | строка |
| `product.deliveryType` | модель поставки | `"SaaS"` \| `"on-prem"` \| `"hybrid"` |
| `product.guiLanguage` | язык интерфейса (**ru** — требование) | `"ru"` \| `"en"` |
| `product.productPageUrl` | публичный URL страницы | строка |
| `product.pricingUrl` | URL прайса / порядка ценообразования | строка |
| `product.class` | класс(ы) ПО, коды | массив строк, напр. `["05.09"]` |
| `product.description` | описание функций | строка |
| `product.purpose` | назначение / область | строка |
| `product.programmingLanguages` | языки программирования | массив строк |
| `product.expertDemo.url` / `.login` / `.password` | демо-доступ для эксперта | строка |
| `support.contactFio` / `contactEmail` / `contactPhone` | контакты техподдержки в РФ | строка |
| `support.lifecycleDocUrl` | URL документации жизненного цикла | строка |

| `tech.infraLocation` | локация инфраструктуры | `"RU"` \| `"иное"` |

### 3. Депонирование (Роспатент)
Закрывается **загрузкой файлов** `dep_*` (снимок, реферат, фрагмент кода, цепочка прав,
заявление, свидетельство). Через MCP пока **не заполняется** — делается в UI (экран «Документы»)
или через API артефактов. Просто сообщи человеку, что осталось загрузить (видно в `get_checklist`).

### 4. Артефакты и проверки
Нужны файлы **SBOM** и **HAR** (загружаются в UI / API артефактов), затем `run_checks`.
Проверки: правило 30% (`finance`), лицензии OSS, сетевой аудит, атрибуты страницы.
Через `patch_product` эти пункты не закрыть — нужны артефакты. `run_checks` пересчитывает статус.

### 5. Подача
| Путь | Смысл | Тип |
|---|---|---|
| `submission.sentToPortal` | заявление отправлено на портал | bool ⚠️ |

Пункт «Стадии 1–4 закрыты» закрывается автоматически, когда закрыты предыдущие.

## Что НЕ выдумывать

Поля с ⚠️ — **внешние факты**. Их знает только человек:
`hasUKEP`, `esiaConfirmed`, `noEnsDebt`, `pp325Checked`, `sentToPortal`.
Не ставь `true`, пока человек не подтвердил. Коды классов ПО и юридические формулировки —
тоже сверяет человек по `reestr.digital.gov.ru`, ты только записываешь.

## Цель достигнута, когда

`get_checklist` возвращает `nextStageId: null` и `checksOverall: "PASS"` — маршрут закрыт,
значения можно переносить в форму на портале (экран «Подача» отдаёт готовые поля).
