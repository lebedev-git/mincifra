# Платформа подготовки к реестру российского ПО

Локальная веб-платформа поверх пайплайна (`../`). Позволяет через браузер завести
продукт, загрузить артефакты, запустить технические проверки, вести гейты G0–G5 и
сгенерировать пакет досье `.docx`.

## Быстрый старт

```bash
cd pipeline/platform
node server.js          # или: npm start
```

Открыть **http://localhost:3000**.

- Порт: переменная окружения `PORT` (по умолчанию `3000`).
- Каталог данных: `REESTR_DATA_DIR` (по умолчанию `platform/data`).
- Автозаполнение по ИНН (опционально): `DADATA_TOKEN` — API-ключ DaData. Без ключа
  функция выключена, платформа полностью офлайн. С ключом на карточке появляется
  кнопка «Заполнить по ИНН» (подтягивает наименование/ОГРН/адрес; данные — черновик,
  проверяет человек). Ключ используется только на сервере, в браузер не передаётся.

Нужен Node.js (проверено на v26) и модуль `docx` (используется генератором досье).
`docx` ищется автоматически: сначала как локальная зависимость, затем в глобальном
npm-каталоге. Если он не найден — установите `npm install -g docx` (или локально
`npm install docx` в каталоге платформы). Путь пользователя нигде не зашит.

## Как «пощупать»

1. **Продукты** → «+ Новый продукт» → ввести имя. Карточка заполнится из шаблона
   `../product.example.json`.
2. **Карточка** → отредактировать поля, «Сохранить». Загрузить артефакты:
   - **SBOM** — CycloneDX JSON (`syft <target> -o cyclonedx-json` или `cdxgen`);
   - **HAR** — DevTools → вкладка Network → «Save all as HAR».
   Для быстрой демонстрации подойдут примеры `../02_checks/samples/`.
3. **Проверки** → «Запустить». Появится таблица с бейджами PASS/WARN/FAIL:
   правило 30%, лицензии OSS, сетевой аудит, страница продукта.
4. **Трекер** → гейты G0–G5 с чек-боксами. Гейт **G3** заполняется автоматически из
   результатов проверок (редактировать нельзя).
5. **Документы** → «Сгенерировать досье» → скачать 4 `.docx`.

## Архитектура

```
platform/
  server.js            точка входа: node:http, роутинг API + отдача web/
  core/
    store.js           data-слой (файловый) — ЕДИНАЯ точка замены на БД
    router.js          сопоставление метод+путь → обработчик (:params)
    http-util.js       чтение тела, JSON/файловые ответы, MIME
    tracker.js         модель гейтов G0–G5, расчёт готовности, авто-G3
    checks-adapter.js  обёртка над ../02_checks/checks.js
    docs-adapter.js    обёртка над ../03_docs/dossier.js
  api/                 products · artifacts · checks · docs · tracker
  web/                 vanilla-фронтенд (index.html, app.js, ui.js, styles.css)
  data/                рантайм-хранилище (создаётся автоматически)
```

**Ядро не дублируется:** платформа вызывает существующие модули проверок и генерации
через адаптеры. Логика проверок — в `../02_checks/checks.js`, генерация — в
`../03_docs/dossier.js`; CLI-скрипты (`run_checks.js`, `gen_dossier.js`) используют те же
модули.

### REST API

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/api/products` | список + сводка (%, статус проверок) |
| POST | `/api/products` | создать из шаблона (`{name, shortName}`) |
| GET/PUT/DELETE | `/api/products/:id` | карточка |
| GET | `/api/products/:id/artifacts` | список артефактов |
| PUT | `/api/products/:id/artifacts/:kind` | загрузка `sbom`/`har` (сырое тело, `?name=`) |
| POST | `/api/products/:id/checks` | запустить проверки |
| GET | `/api/products/:id/report` | последний отчёт |
| GET/PUT | `/api/products/:id/tracker` | гейты (PUT: `{items:{id:bool}}`) |
| POST | `/api/products/:id/dossier` | сгенерировать досье |
| GET | `/api/products/:id/dossier/:file` | скачать `.docx` |

## Переезд на сервер (когда понадобится)

Архитектура к этому готова:

- **Хранилище.** Весь доступ к данным изолирован в `core/store.js`. Для многопользовательского
  сервера — заменить файловую реализацию на PostgreSQL (СУБД из реестра РФ), сохранив сигнатуры
  функций. Остальной код (API, адаптеры, фронтенд) не меняется. Артефакты и `.docx` при этом
  логично хранить в объектном хранилище РФ (Yandex Object Storage / Selectel S3).
- **Конфигурация.** Порт и каталог данных уже берутся из env.
- **Развёртывание.** Node-процесс за `nginx` (TLS, статика) на российском хостинге.
- **Что добавить для мультиарендности:** аутентификация (ЕСИА/OAuth), привязка продуктов к
  организации, роли, аудит-лог. Это отдельный слой поверх текущего API — ломать существующее
  не требуется.
- **Соответствие самой платформы требованиям реестра:** фронтенд уже без внешних CDN/шрифтов,
  интерфейс на русском — платформа сама не нарушает локализационные требования.

## Ограничения

- Однопользовательский режим, без аутентификации (рассчитан на локальный запуск).
- Проверки работают по предоставленным артефактам (SBOM/HAR), а не сканируют исходный код —
  это осознанное разделение ответственности (артефакты готовит инженер продукта).
- Значения с пометкой «СВЕРИТЬ» (сроки, коды классов, форматы вложений) проверяйте на
  `reestr.digital.gov.ru` перед подачей.
- Сгенерированные `.docx` — каркасы; правовые формулировки проверяет юрист правообладателя.
